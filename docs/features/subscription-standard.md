### 변경 사유
1. **선택의 역설 (Paradox of Choice)** - 고객 의사결정 단순화
2. **YAGNI 원칙** - MVP 단계에서 필요한 것만 구현
3. **검증 우선** - 단일 tier로 핵심 가치 검증 후 확장
4. **이너 서클 브랜딩** - 프로그램명과 상품명 분리로 확장성 확보
5. **Roommate 컨셉** - "TBR의 룸메이트가 되어보세요"

## 📊 현재 멤버십 구조 (Notion v3.0)

### ❌ 비회원 (0원)
- 상시 할인: **없음**
- 무료 배송: **없음** (일반 배송비 적용)
- 기부 참여: **불가**
- 시즌 서프라이즈: **불가**

### 🏠 Roommate (9,900원/월)
- 상시 할인: **10%** (모든 상품)
- 기부 참여: **1%** (구매금액 자동 기부)
- 무료 배송: **3만원 이상**
- 시즌 서프라이즈: **제공** (깜짝 혜택)
- 신상품 얼리 액세스: **제공**
- 생일 특별 혜택: **제공**

## 💡 4가지 핵심 가치 (SAVE-IMPACT-BELONG-SURPRISE)

| 가치 | 혜택 | 설명 |
|------|------|------|
| 💰 **SAVE** | 10% 상시 할인 | 모든 상품 상시 10% 할인 |
| 💝 **IMPACT** | 1% 기부 참여 | 구매금액 1% 자동 기부 |
| 🚚 **BELONG** | 3만원↑ 무료배송 | 멤버 전용 무료 배송 |
| 🎁 **SURPRISE** | 시즌 서프라이즈 | 특별한 깜짝 혜택 |

## ✅ 주요 업데이트 포인트

다른 페이지에서 구독 내용을 업데이트할 때 반드시 포함해야 할 내용:

1. **브랜드명**
   - ❌ 삭제: "TBR 멤버십", "스탠다드", "프리미엄"
   - ✅ 사용: **🏠 Roommate: 9,900원/월**

2. **핵심 메시지**
   - 💡 "10% 상시 할인 + 1% 기부 + 3만원↑ 무료배송!"

3. **혜택 요약 (v3.0)**
   - 할인: 10% 상시 할인 (NOT 포인트)
   - 기부: 1% (NOT 5%)
   - 배송: 3만원 이상 무료 (NOT 5만원)
   - 시즌 서프라이즈: 깜짝 혜택

## 🔐 성인인증 시스템 (PASS)

### PASS 본인확인 서비스
| 항목 | 내용 |
|------|------|
| **서비스** | SKT PASS 본인확인 |
| **방식** | CI/DI 기반 실명 인증 (휴대폰 인증) |
| **적용 시점** | 회원가입 시 1회 |
| **재인증** | 주문 시 불필요 (가입 시 인증 완료) |
| **법적 근거** | 청소년보호법 - 성인용품 판매 시 성인 확인 의무 |

### 인증 플로우
```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  회원가입   │ ──▶ │ PASS 인증   │ ──▶ │ 19세 확인   │
│   페이지    │     │   팝업      │     │   완료      │
└─────────────┘     └─────────────┘     └─────────────┘
        │                  │                   │
        ▼                  ▼                   ▼
   이메일/비번        CI/DI 수신          가입 완료
   입력               (본인 확인)         (성인 인증됨)
```

## 💳 결제 시스템 (TossPayments)

### 결제 유형
| 유형 | 방식 | 설명 |
|------|------|------|
| **구독 결제** | 빌링키(Billing Key) | Roommate 월 정기결제 |
| **일반 결제** | 단건 결제 | 상품 구매 시 |

### 지원 결제 수단
- 💳 **신용/체크카드**: 국내 모든 카드사
- 🏦 **계좌이체**: 실시간 계좌이체
- 🟡 **카카오페이**: 간편결제
- 🔵 **토스페이**: 간편결제

### 주요 API
```yaml
빌링키 발급: POST /billing/authorizations/card
정기결제 실행: POST /billing
일반결제 승인: POST /payments/confirm
결제 취소: POST /payments/{paymentKey}/cancel
```

### 정기결제 스케줄
```
매월 결제일 (가입일 기준)
     │
     ▼
Vercel Cron (매일 자정)
     │
     ▼
TossPayments API 호출
     │
     ▼
결제 처리 → Supabase DB 업데이트
     │
     ▼
Webhook → Edge Function (상태 변경 알림)
```

### Webhook 이벤트
- `PAYMENT_DONE`: 결제 완료
- `PAYMENT_CANCELED`: 결제 취소
- `BILLING_FAILED`: 정기결제 실패
- `BILLING_SUCCESS`: 정기결제 성공
